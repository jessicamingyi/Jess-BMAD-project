### Code review (adversarial, edge case, verification gap)

No high or medium defects. The interactions between TS-42, TS-43 and TS-62 check out: read-only beats saving-off in the banners (`src/game/banners.ts:28`); a saving-off tab never calls `persist`; the TS-62 top-up adds only solution digits and keeps each one only if `grade()` still equals the target (`src/engine/generator.ts:83`).

| ID | Finding | Source | Severity | Disposition |
|---|---|---|---|---|
| R1 | **The save lock can stay held for the page's lifetime.** If the lock is granted *after* the 3 s give-up and `loadSaved` then hangs, nothing releases it: the timeout callback ran while `lockState.lock` was still null, and the `finally` never runs. Every tab opened later becomes read-only ("open in another tab") although no tab is saving. Re-checked by the parent. Fix: `if (gaveUp) release()` straight after the lock is stored, plus a test with a late lock and a hanging load. | `src/ui/boot.tsx:78-81,88-96` | low (needs wedged IndexedDB and a slow lock grant) | defer (new ticket) |
| R2 | **One race makes the saving-off wording untrue.** Unreadable data is backed up, then the timeout fires while the defaults write is in flight. The write lands, but this tab shows "Anything saved before is left untouched". The next launch loads clean defaults with no unreadable notice; the data survives only in the backup key. The code comment already accepts this race, but the TS-43 wording now promises otherwise. Re-checked by the parent. | `src/persistence/store.ts:135-140`, `src/content/copy.ts:214` | low (needs unreadable data and a write at the 3 s edge) | accept, and record in `deferred-work.md` |
| R3 | **TS-43's "a saving-off tab gives the lock back" is only tested with a fake lock.** The smoke journey checks the banner and one digit, but never opens a second tab to show it can save. | `tests/ui/autosave.test.ts`; `scripts/smoke/journeys/persistence.ts:156-171` | low | defer (add to TS-58) |
| R4 | **Nothing guards the generator's success rate after TS-62.** The tests run pinned seeds; the "finishes well inside the Free Play timeout" criterion rests on one-off timings written in the spec. | `tests/engine/generator.test.ts:17-41`; `spec-ts-62-lower-difficulty.md` | low | defer (add to TS-51) |
